# HUSH.GG 선수 분석 리포트 · Just Joke 작성 가이드

선수 탭의 "📋 선수 분석 리포트" 본문을 쓰는 규칙이다. 본문은 Claude가 데이터를 보고 직접 쓴다.
섹션 위의 숫자 칩(순위·MVP·듀오·레이더)은 사이트가 실시간으로 계산하므로 글에서 그대로 반복할 필요는 없다.

## 저장 위치와 형식
- `data/reports.json` (`index.html` 의 `PLAYER_REPORTS` 로 Actions가 주입)
- 선수 이름 → 객체
```json
"이또": {
  "asof": 50,
  "one": "한 줄 요약 (선수를 한 문장으로)",
  "now": "최근 흐름 (가장 최근 출전 회차 이야기, 2~3문장)",
  "s": {
    "lane":  "챔프폭 · 라인전 · 교전",
    "sense": "게임 센스 · 시야 (시야·오브젝트·FB·포탑)",
    "mind":  "오더 · 경험 · 멘탈 (참가 횟수, MVP/ACE, 패배 다음 판, 연승·연패, 꾸준함, 경기 시간별)",
    "syn":   "시너지 (같은 팀 듀오, 바텀 듀오 15분 골드, 먹잇감·천적)",
    "weak":  "약점 및 총평 (가장 약한 지표 + 구체적인 다음 과제)"
  }
}
```
- `asof` = 이 글이 반영한 마지막 경기 번호. 갱신한 선수만 최신 경기 번호로 바꾼다.
- 판수별 분량: 10판 이상 → 5개 섹션 전부 / 3~9판 → 가능한 섹션만, 짧게 / 1~2판 → `one` + `lane` (+ `weak`)

## 문체 규칙
- 한국어, "~다" 평서체. 섹션당 2~4문장.
- 모든 주장에 숫자 근거. dossier에 없는 사실을 지어내지 않는다.
- 아첨 금지. 약점 지표를 분명히 짚고, 바로 해볼 수 있는 구체적인 과제로 끝낸다.
- 순위는 "원딜 8명 중 1위"처럼 같은 라인 기준임을 밝힌다. 스카우팅 순위는 판수 보정 순위다.
- 판수가 적으면 표본이 작다는 점을 밝힌다.
- 본문에 이모지·HTML 태그를 넣지 않는다.
- 칭호(인간 방패·한우물 등)는 사이트에서 없앴다. 본문에 칭호 이름을 쓰지 않고, 필요하면 지표와 순위로 직접 말한다.
- 다미: 순위 집계 제외 대상이라 "랭킹 숨김" 같은 말은 쓰지 않는다. 다른 선수 글에서 다미를 듀오·천적으로 언급하지 않는다.
- 게스트·이벤트 참가자도 리포트를 쓴다. 데뷔 패배를 조롱하지 않는다.

## 갱신 절차
1. `node tools/report_dossier.js index.html /tmp/dossier.txt`
   - 저장된 `asof` 이후 경기에 출전한 선수와 리포트가 없는 선수만 뽑는다. 첫 줄에 대상 명단이 나온다.
   - 대상이 0명이면 할 일 없음.
2. 대상 선수마다 dossier와 기존 리포트(`기존리포트:` 줄)를 보고 다시 쓴다.
   - `now` 는 새 회차 내용으로 교체. 섹션은 숫자가 바뀐 곳을 고치고, 흐름이 바뀌었으면 결론도 바꾼다.
   - `asof` 를 최신 경기 번호로.
3. Just Joke 8장을 새로 쓴다 (위 규칙).
4. `data/reports.json` · `data/just_joke.json` 에 저장 (다른 선수 항목은 그대로 둔다) → 커밋 → main 에 푸시
   - 푸시하면 Actions("HUSH.GG 경기 업데이트")가 자동으로 돌아 `index.html` 에 주입한다 (새 경기는 가져오지 않음).

## Just Joke (뉴스 탭) — 리포트와 같은 업데이트에서 함께 쓴다 (2026-11-27 개편)
- `data/just_joke.json` (`JUST_JOKE` 로 주입). 새 내전 날이면 **8장 전부 새로** 쓴다.
- 카드 형식: `{"t": "뉴스 헤드라인", "b": "본문 2~3문장, 강조는 <b>…</b> 만", "tag": "유형"}`

### 기준: 8장 모두 그날 내전(그날 치른 2~3경기)이 출발점
- 그날 경기를 끝낸 멤버들이 보러 들어오는 코너다. **모든 카드의 주인공은 그날 출전한 선수**로 하고, 그날 경기 장면이나 결과에서 이야기를 시작한다.
- 아래 유형은 그 이야기를 보는 각도다 (예: 오늘 맞라인 두 사람의 통산 맞대결, 오늘 경기로 넘은 이정표, 오늘 이긴 조합의 궁합).

### 카드 유형 (8장을 아래에서 고르게 섞는다. 같은 유형은 최대 2장)
| tag | 유형 | 예 |
|---|---|---|
| 쌍둥이 | 지표는 비슷한데 결과가 다른 두 선수 (둘 다 10판+) | "킬은 재우가 더 많다, 그런데 승리는 6 대 35" |
| 맞대결 | 두 선수가 적으로 만났을 때의 누적 전적 (3판+) | "승률 78% 이또가 한 번도 못 이긴 상대" |
| 카운트다운 | 다음 이정표까지 남은 숫자와 예상 시점 | "이또 통산 350킬, 400킬까지 50개" |
| 기록 | "~이후 처음", "~한 유일한/N번째" 같은 역사 맥락 | "생불, 12연승… '두 자릿수 연승 클럽' 세 번째 회원" |
| 첫 10판 | 같은 판수 구간끼리 비교 | "첫 10판 성적표, 현규 10승 · 이또 7승" |
| 궁합 / 징크스 | 같은 팀 최다 조합, 같이 나오면 이기는/지는 조합 (4판+) | "재우·한울, 같은 팀 네 번에 네 번 다 졌다" |
| 맞라인 / 반전 / 흐름 | 오늘 맞라인 비교, 진 팀이 딜은 더 넣은 판, 연패 탈출·연승 흐름 | "탑 딜은 용인이 더 넣었다, 이긴 건 비비" |
| 오늘 | 그날 경기의 한 장면 | "백호, 두 번째 판에 그 판 최고 딜" |

### 말투 (사람이 쓴 커뮤니티 뉴스처럼)
- 헤드라인은 기사 제목처럼: 이름 + 핵심 숫자 + 반전. 쉼표·말줄임표로 끊어 읽히게.
- 본문은 구어체가 섞인 기사체. "~했다는 게 반전", "~라고 해두자", "참고하시길", "~라는 평" 같은 사람 말투를 쓰되, 매 카드 같은 표현을 반복하지 않는다.
- 피할 것: "~다. ~다. ~다." 짧은 문장 나열, 숫자만 줄줄이 늘어놓기, 교훈조 마무리, 이모지, 대시(—).
- 실제 선수가 한 말처럼 따옴표 발언을 지어내지 않는다.

### 규칙
- **한 선수가 주인공인 카드는 8장 중 최대 2장.** 두 사람이 나란히 나오는 카드(쌍둥이·궁합·맞대결)는 두 사람 모두 주인공으로 센다. 비교 대상으로 이름만 나오는 것은 세지 않지만, 같은 사람이 비교 대상으로도 계속 나오지 않게 분산한다.
- 모든 숫자는 데이터에서 코드로 계산해 확인한다 (합계·비율·연승·맞대결 전적).
- 다미는 다루지 않는다. 첫 출전 선수의 패배, 게스트·외부 인원은 놀림 소재로 쓰지 않는다. 징크스 카드는 가볍게, 한 사람만 겨냥하지 않는다.
- 외부 비유 금지 (스포츠 승강급 등). 이또 언급 가능.

## 운영 알림 (업데이트 때 확인)
- 전체 경기 수가 **100판 이상**이 되면, 보고할 때 "챔피언의 주인 최소 판수(지금 3판, index.html 의 OWNER_MIN)를 올리자"고 이명우에게 제안한다. 직접 바꾸지는 않는다.
- 선수 탭 헤더 일러스트 = 챔피언의 주인인 챔피언 중 승률 1위의 기본 스킨 (주인 챔피언이 없으면 일러스트 없음). 이명우가 특정 챔피언 스킨을 지정하면 `index.html` 의 `CHAMP_SKIN` 에 {"챔피언id": 스킨번호} 로 넣고, 얼굴이 빗나가면 `SKIN_FOCUS` 에 "id_번호": [x, y] 로 조정한다.
